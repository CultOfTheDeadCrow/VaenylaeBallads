<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → StaticPopupDialogs editbox | Player types a song name into the popup edit box |
| Addon → WoW API SendChatMessage/DoEmote | Song line text passed to WoW server |
| Repo → Faebright WoW AddOns directory | File copy; no network involved |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Input Validation | StaticPopup editbox → VaenylaeBardSongs | accept | Song name is user-supplied string stored in SavedVariables and displayed in UI. No injection surface — it is never passed to eval, exec, or external APIs. WoW engine handles all string storage. |
| T-03-02 | Input Validation | Song line text → SendChatMessage | accept | Line text is passed directly to SendChatMessage. WoW server validates and truncates chat messages (255-char limit). No client-side injection risk beyond WoW's own enforcement; unchanged from 1.12.1 behavior. |
| T-03-03 | Information Disclosure | SavedVariables (VaenylaeBardDB) | accept | Local to the WoW install; serialized by WoW engine to a per-character .lua file; no external exposure. No secrets stored. |
| T-03-04 | Tampering | cp -r deployment | accept | File copy from trusted local repo to local WoW directory; no network, no integrity check needed. If path is wrong, ls verification step catches it before in-game test. |

ASVS L1 requirements satisfied by WoW engine. No auth, no server calls beyond WoW API, no user secrets.
</threat_model>
